### F-01 — Normalization emits confidently wrong evidence from partial or global matches

**Location:** src/lifemate/runtime/normalize.py:61–88 and :123–144. Consumers:
runtime/loop.py normalization before planning/actions, runtime/context.py payload,
and metrics/asr.py critical amount/time extraction and supersession filtering.
**Criteria:** AC-09 and AC-30; related K32/K38/K40 and multi-goal context.

Expected: parse a complete supported quantity and associate dates/corrections with
the affected expression. Unsupported or unresolved interpretation must carry
uncertainty, without inventing a different certain amount/date or withdrawing an
unrelated goal. Actual authored-input results, at sample time
`2026-11-10T10:00:00+07:00`, timezone Asia/Ho_Chi_Minh:

- `chuyển mười ba triệu cho mẹ` emits **3000000**, matching only `ba triệu`, with
  `uncertain:false` and no uncertainties. The request says thirteen million.
- `chuyển -500 nghìn` emits **+500000**, dropping the sign, also certain.
- `đặt nhắc việc hôm nay 17 giờ và mai 8 giờ` emits **tomorrow** for both clocks;
  the first explicitly says today. `if "mai" in lower` is utterance-global.
- `chuyển 500 nghìn và đặt xe năm giờ à không, năm rưỡi` marks the independent
  transfer amount **superseded:true**, and reduces effective_text to `năm rưỡi`.
  The local ride-time correction does not cancel the transfer.

Reproduction: run review.r1.probes.py; the corresponding four objects are preserved
in review.r1.probes.json. This is deterministic helper behavior with no model.
The incorrect values enter both the planner/action context and supplied-ASR critical
metrics. Keeping raw text lets a model potentially recover, but does not make the
helper's conflicting certain evidence correct. Existing tests cover isolated
phrases and whole-request correction, missing these compounds.

**Minimal corrective action:** enforce complete numeric-expression boundaries/sign
handling, and scope time qualifiers/correction supersession to the associated
expression/goal. Where that cannot be established conservatively, surface
uncertainty instead of a certain partial value or global cancellation. Preserve
unaffected intents/negation/values. Add compound/signed amount, mixed-day and local
correction regressions, including the downstream critical-slot comparison consumer.
No broad language-accuracy guarantee or real-model run is required to fix this.

### F-02 — The retained SDK read smoke always fails the new goal-planning boundary

**Location:** scripts/smoke_runtime.py:15–24 and :45–47; interacting
src/lifemate/runtime/loop.py:89–104 / runtime/goals.PolicyPlanner.
**Criteria:** AC-33; Plan §8 explicitly retains this script's workflow meaning.

Expected: ReadOnce supplies one eligible read, then internal DONE, preserving the
documented one-read smoke semantics. Actual: ReadOnce exposes only next_action.
The new loop falls back to PolicyPlanner, consumes its first CALL as a GoalPlan
and rejects it; the retry consumes DONE and rejects that too. Planning remains

Reproduction: review.r1.probes.py imports the actual script without its main block
and passes its actual ReadOnce to infer with an authored FakeEnv. Result

No real ToolEnv was opened. This is an introduced compatibility regression from
the new loop; original tests now have planner-capable fakes, masking this consumer.
The historical recorded smoke PASS is not evidence that this changed consumer works.

**Minimal corrective action:** give the deterministic smoke a compatible explicit
planner/planning response that does not consume its read/action state, or inject a
suitable planner at the call. Preserve one actual read and terminal DONE. Add an
injected behavioral test for this real script consumer, beyond --help; do not run
real-data smoke merely to satisfy current software review.

### F-03 — Retained kit utilities bypass the new protected-input output policy

**Location:** scripts/check_trajectories.py:77, scripts/check_evaluator.py:43,
scripts/smoke_runtime.py:32 and :49. Shared guard artifacts.external_output requires
callers to pass inputs; these calls omit them. **Criterion:** AC-36; Plan §§3/8.

Expected: runtime artifacts are outside selected kit/input roots, and output plus
sidecar destinations are checked before work. Actual: these utilities call
external_output(out) with no kit/input roots. That invocation protects source and
existing destinations but permits a new report within the selected organizer kit.

Reproduction: review.r1.probes.py creates only an OS-temp authored two-scenario kit,
fold and terminal-DONE trajectories, then invokes the actual
scripts/check_trajectories.py with `--out <synthetic-kit>/forbidden-report.json`.
The child exits **0**, prints `status:PASS`, and creates that file inside the kit.
The exact outcome is `utility_output_inside_kit` in review.r1.probes.json. No real
organizer input was read/written. The other two kit-bearing utilities have the same
static call-site omission; smoke_runtime's sidecar is also not preflighted.

This output-guard limitation existed in the baseline, so it is **not claimed as a
newly introduced overwrite regression**. It remains an unfulfilled newly approved
full-application safety contract in changed/retained consumers. No-clobber now
protects existing files, reducing impact; it does not enforce the required root
boundary or prevent new dataset-derived files being placed in organizer assets.

**Minimal corrective action:** resolve the actual direct/wrapper kit root and pass
it plus other protected input files to the guard at all affected utility output
sites. Validate sidecar collisions/existence before runtime, using the same policy
as workflows.predict. Add authored direct/wrapper/path-alias and sidecar negative
checks plus a successful external destination. Preserve existing organizer bytes
and the explicit no-overwrite contract.
