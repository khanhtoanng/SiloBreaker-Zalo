# Codex host notes

- Local plugin: the bundle root contains `.agents/plugins/marketplace.json` pointing at `./plugins/ai-sdlc`. From its parent directory use `codex plugin marketplace add /absolute/path/to/AI_SDLC_Local_Plugin_v0.5.0`, then `codex plugin add ai-sdlc@ai-sdlc-local` where supported. Alternatively use Codex's `/plugins` manager; inspect `codex plugin list`. Restart/reload to see updates. The local marketplace name is `ai-sdlc-local`.
- Portable manifest `plugins/ai-sdlc/plugin.json` + `skills/` is authoritative; no duplicated `.codex-plugin` overlay is needed.
- For hosts/versions lacking plugin installation, **fallback** is a deliberate user-level copy of `skills/{sdlc-work,sdlc-setup,sdlc-doctor}` to `~/.agents/skills/` (or a single project `.agents/skills/`); this is a snapshot requiring manual re-copy after plugin changes, not live plugin installation.
- Codex uses `AGENTS.md` and supports custom `.codex/agents/*.toml` definitions, but do not generate a custom reviewer config by default. Use an actual fresh subagent for independence. A reviewer instruction to avoid edits does not enforce sandbox read-only: subagents inherit the parent session's sandbox and approval mode.
- Distinguish an active repository from additional sibling paths. For local CLI multi-repo work, use `codex --sandbox workspace-write --ask-for-approval on-request --add-dir ../frontend --add-dir ../flyway --add-dir ../terraform` from the selected working root when appropriate. `--add-dir` is a host permission setting, never workflow approval. Verify actual access and root scoping before making edits; do not claim cross-root access implicitly.
- Codex `/review` and `codex review` provide useful review evidence but are not automatically equivalent to verified independent host-native subagent isolation.
